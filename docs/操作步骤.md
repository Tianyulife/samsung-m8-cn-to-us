本文按本次成功实验顺序整理，保留失败原因与恢复要点。当前显示器已经升级完成，日常核验直接使用第 9 节；第 3—7 节是旧固件操作记录，**不要在当前 1720.7 上直接重放写入命令**。1720.7 的只读 SDK 通道已验证，重新 root 和写入尚未验证。

## 3. 1651.1 临时 root 与原始状态

使用已审阅的 archive-root 路线：SDK 命令执行 → 有 capability 的 .NET → 私有挂载命名空间 → 三星归档启动器 → 经认证的 root agent。

本机验证得到 UID/EUID/GID/EGID 全部为 0，SMACK 标签仍为 User。没有配置持久 root，没有禁用 UEP，也没有使用物理内存内核修改路线。

本地入口为 `verify-temporary-root.py`，载荷为 `root-payloads31/`。该入口会实际执行临时提权，名字中的 verify 不代表仅做无副作用的检查。它接受 JSON 命令列表并记录返回值，不能把电脑上的普通 shell 当作设备 root shell。

原始状态必须分别记录：

```text
Local Set：读取枚举 65（CHI_DTV），原始存储 63
Preventing Import：13
db/comss/countrycode：CN
com.samsung/featureconf/was.use_china_server：true
db/system/country：29（本次不改）
```

本次 root 会话结束时核对 `/etc/passwd`、`/usr/share/sdbd/public.pem` 前后哈希相同，工具报告 `system_files_unchanged=true`、`staging_cleaned=true`。临时 root 结束后，普通 SDK 通道仍是 SDK 权限。

## 4. 备份与离线分析

### 配置库

对 `/opt/data/fconfig/fconfig.db` 使用 SQLite 在线 `.backup`，执行 `PRAGMA integrity_check`，保存到本地并校验哈希。不能把正在运行的数据库普通文件复制视为等价的一致性备份。

原始服务切换备份：`firmware-analysis/region-trial/fconfig-before.db`。

### 原生 NVRAM

使用三星 `FCNvramMap::Read` 按 4096 字节分块读取，共 65536 字节。通过主机接收数据并比较 SHA256、长度、已知字段及变更范围。

| 本地备份 | 关键字节 | SHA256 |
| --- | --- | --- |
| `firmware-analysis/localset-trial/native-eeprom-before.bin` | Local Set=63，Import=13 | `4bc4bb24f4fa6281a9c6f8131580bc9cf659c48b7bc55964da75082ae3678a45` |
| `firmware-analysis/localset-trial/native-eeprom-after.bin` | Local Set=1，Import=13 | `6145178ccf41f72c22d7106fc63bdc923b00192190309beeeb67073b04357127` |
| `firmware-analysis/import-trial/native-eeprom-before.bin` | 同上，第二阶段基线 | `6145178ccf41f72c22d7106fc63bdc923b00192190309beeeb67073b04357127` |
| `firmware-analysis/import-trial/native-eeprom-after.bin` | Local Set=1，Import=0 | `c7e6461f398b891ad4ab5dd321d135cd2a0b197dc567d73d063f11f8b8e15fcd` |

这些不是整机磁盘备份，也不包含完整恢复系统。文件权限设为 0600，不应公开其中的设备专属数据。

**不要使用 `localset-trial/eeprom-before.bin` 恢复。**它是早期经普通 `dd` 读取产生的全 FF 数据。文件长度正确不代表设备接口读到了真实 NVRAM。

### 两版官方固件

离线下载、解密和提取的对象为国行 1651.1 与美国型号对应的全球 1720.7；保存于 `firmware-analysis/CN-1651.1/`、`firmware-analysis/US-1720.7/`。来源、完整 ZIP 哈希与解包说明见 [固件分析](../firmware-analysis/README.md)。本机升级采用 OTA，没有执行解包镜像的原始刷写。

## 5. 先完成海外服务切换

本次最早单独改国家 US 后 Apps 报错误 22，恢复 CN 后恢复正常。后续成功组合为：

1. 经原生接口将 WAS 中国服务器开关设 false。
2. 经 comss 原生 D-Bus 方法将 Smart Hub 服务国家设 US。
3. 读取实际认证、安全端点，确认转为 `.com`。
4. 用户退出并重开 Apps，确认出现海外应用、无新增错误。

本次辅助程序与设备端调用如下，仅说明已执行的底层动作；这些调用位于具备相应权限的设备会话：

```sh
/usr/bin/dotnet /home/owner/share/tmp/sdk_tools/m8-region-trial/RegionTrial.dll set-overseas
gdbus call --system --dest comss.server --object-path /comss/server --method comss.server.interface.comss_set_gpm_countrycode US
```

辅助程序通过 `libfconfig.so` 的 `fconfig_set_bool` 修改单个完整键 `com.samsung/featureconf/was.use_china_server`，没有直接批量 UPDATE SQLite。国家通过既有服务接口写入，避免只改静态默认文件而运行服务仍使用旧值。

本阶段部署 `restore-cn.sh` 和 600 秒 watchdog；用户确认成功后设置 `keep-us` 标记，取消自动回退。执行包为 `region-trial/apply-commands-v2.json`；它仍保留早期后台任务继承连接的历史问题，**不是已修订的一键发布工具**。实际参数结果由独立 SDK 会话确认，不能用主机启动器是否超时代替设备读回。

证据：[组合实验](../firmware-analysis/region-trial/trial-status.md)。

## 6. 工厂 Local Set 改为 US

原菜单没有 US，底层全局枚举中存在 US=1。研究确认工厂参数 UID194 的 getter 和 setter 使用不同表示：

```text
factory_get_data(194) → 原始 CHI_DTV 返回全局枚举 65
factory_set_data(194, 63) → 写回本机原始 CHI_DTV 存储值
factory_set_data(194, 1)  → 写 US
```

执行顺序：

1. 保存本机有效原生备份，核对 DLL 与设备工厂库哈希。
2. `preflight-write-original` 写回原值 63，确认读取仍为枚举 65。
3. 部署恢复脚本，启动 600 秒自动回退。
4. `LocalSetTrial.dll set-us` 写入 UID194=1。
5. 独立读取 getter 和原生存储，确认枚举 1、仅 `0x3E23` 从 63 变 1。
6. 用户确认 Apps 正常后，运行 `keep-result.py` 写入并确认 `keep-localset` 标记。

| 文件（位于 `firmware-analysis/localset-trial/`） | 用途 |
| --- | --- |
| `helper/Program.cs`、`stage-helper.py` | 辅助程序源码与部署 |
| `native-backup-commands.json` | 原生备份命令清单 |
| `apply-commands-v2.json` | 本次成功使用的带保护写入清单 |
| `verify-storage.py`、`storage-diff.json` | 独立存储验证与结果 |
| `keep-result.py` | 此阶段确认后保留结果 |

`keep-result.py` 要求当时 Preventing Import=13；当前值已为 0，因此不应重放这个历史阶段脚本。

本次原值写回预检成功，但没有实际完成 US → CHI_DTV → US 的完整往返恢复演练。

## 7. Preventing Import 测试 0

这是在 Local Set 已经 US、海外 Apps 已正常的基础上进行的独立实验，不把它表述为获取海外 Apps 或触发 OTA 已证明必需的前提。

1. 再保存一份阶段基线：Local Set=1、Preventing Import=13。
2. `ImportTrial.dll preflight` 写回原值 13 并核对。
3. 部署恢复脚本，启动 600 秒 watchdog。
4. `ImportTrial.dll set-zero` 调用 `factory_set_data(761, 0)`。
5. 独立读回确认 0，原生 NVRAM 仅 `0x3E65` 从 13 变 0。
6. 可见 Local Set 名单从 2 项增至 31 项。
7. 用户确认 Apps 正常后，通过此阶段 `keep-result.py` 创建 `keep-import` 标记。

对应文件位于 `firmware-analysis/import-trial/`：`apply-commands.json`、`verify-storage.py`、`storage-diff.json`、`localset-list-diff.json`、`keep-result.py`。源码为 `helper/Program.cs`。

本机写入试验执行在 1651.1 上。0 的实测意义是解除本机该项地区过滤，不能据此确定所有全球型号的出厂值。

## 8. 正常重启与 OTA

确认三个阶段的保留标记存在，避免 watchdog 回退已通过的设置。本次保留标记分别是设备相应目录下的 `keep-us`、`keep-localset`、`keep-import`；最终 watchdog 状态均为 `CANCELLED`。

用户手动重启后，通过 `/proc/sys/kernel/random/boot_id` 改变和较短 uptime 确认发生内核重启，而非仅屏幕待机；各字段均保留。

曾尝试用 `systemd-run` 延迟执行 `systemctl reboot`，服务返回状态 5，未重启。之后已停止 timer/service 并确认无待执行 jobs。因此本记录采用**用户手动重启**，不把自动重启方案写成已验证方法。

用户随后通过显示器官方更新界面完成 OTA，并确认版本 **1720.7**、使用无异常。更新完成后按第 2 节重新开启开发者模式并再次手动重启，再进行最终核验。

如果 helper 文件被清理，需要先检查当前 SDK/运行时和工厂库接口，再部署兼容的读取程序；不能因文件缺失就重跑旧固件写入脚本。

## 10. 恢复方案与已验证程度

以下是已保存的恢复入口，**当前不需要执行**。它们在原 1651.1 环境准备并做过原值写回测试；本次未在 1720.7 上验证恢复写入，正式恢复前应重新确认权限、接口和基线。恢复这些地区设置不会降级固件，也不保证撤销商店自行更新的全部应用数据。

顺序必须按阶段反向进行：

1. 将 Preventing Import 恢复 13。
2. 将 Local Set 恢复本机原始存储值 63，并确认 getter 返回 65 / CHI_DTV。
3. 将 WAS 开关恢复 true，服务国家恢复 CN。
4. 读回参数与服务地址，再检查 Apps。

设备端恢复调用如下，需要具备相应权限的会话：

```sh
/usr/bin/dotnet /home/owner/share/tmp/sdk_tools/m8-import-trial/ImportTrial.dll restore-import
/usr/bin/dotnet /home/owner/share/tmp/sdk_tools/m8-localset-trial/LocalSetTrial.dll restore
cat /home/owner/share/tmp/sdk_tools/m8-region-trial/restore-cn.sh | /bin/bash
```

Local Set 的 restore 模式要求 Preventing Import 已为 13。恢复脚本采用 bash 标准输入，因为本次 UEP 曾阻止以普通脚本文件名方式执行；这不代表已关闭 UEP。

不要直接把整份 64 KiB NVRAM 覆盖回设备；其中可能有其他时刻变化的数据。不要把这份备份写入其他机器。

## 11. 复现时的关键限制

- 本机已经成功：无需为了“再验证一次”重跑 apply、preflight、backup-baseline 或 keep 脚本。部分脚本会写原值或覆盖现有备份、证据。
- 旧阶段脚本硬编码 IP、原值及 1651.1 工厂库哈希。1720.7 工厂库哈希已变化；不能简单去掉校验继续写入。
- watchdog 是实验保护，不是开机恢复系统；必须确认它已启动、恢复入口有效，且成功后已取消。后台任务需关闭继承的回传文件描述符，否则可能导致主机等待超时。
- 本次已证明“本机配置切换 → 海外 Apps → 正常重启保持 → 官方 OTA 1720.7 → 再次读取保持”。尚未证明任意国行机器都能复现，也未把硬件/证书身份改成美国销售版本。
